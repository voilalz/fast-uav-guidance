# 软件方案：高速固定翼无人机 GNSS 拒止自主导航系统

> 依据：[总体方案](navigation-design.md) v0.2、[硬件方案](hardware-design.md)
> 代码：[`nav/`](../nav)（嵌入式 C++17 + C99，可在宿主机编译、测试、仿真）

---

## 1. 软件总体架构

软件分布在三个处理器上：

| 处理器 | 软件 | 语言 / 运行环境 | 实时性 |
|---|---|---|---|
| 导航 MCU（STM32H743） | 导航固件：IMU 阵列融合、捷联惯导、ESKF、模式管理、30 Hz 输出、时间基准、相机触发 | C++17（无异常/RTTI/运行期动态内存）+ C99 协议层，FreeRTOS | 硬实时 |
| 视觉计算机（Jetson Orin NX） | 视觉导航服务：采集、视觉里程计、景象匹配、三维地形匹配、TERCOM、参考库管理 | C++17，Linux PREEMPT_RT，CUDA / TensorRT / VPI / OpenCV | 软实时 |
| 飞控（Pixhawk 6X） | ArduPilot + 新增 External AHRS 后端（解析 `NAV_OUTPUT`） | C++（ArduPilot 代码规范） | 硬实时 |
| 地面（离线） | 参考库生产工具链、仿真、数据回放分析 | C++ / Python | — |

```
┌──────────────────────── 导航 MCU（FreeRTOS） ────────────────────────┐
│ ISR: IMU_DR 2 kHz ─► ImuArray::fuse ─► 5 点平均 ─► imu_q（400 Hz）     │
│ T1 NavTask   ◄─ imu_q, meas_q ─► NavCore ─► 30 Hz NAV_OUTPUT ─► 飞控/Jetson │
│ T2 LinkTask  ◄─ UDP(VO_VELOCITY, POSITION_FIX) ─► meas_q                │
│              ─► UDP(CAM_TRIGGER, NAV_PRIOR, TIME_SYNC)                  │
│ T3 SensorTask: 空速/气压/雷达高 50 Hz，磁 10 Hz ─► meas_q               │
│ T4 HealthTask: 自检、看门狗、SD 卡记录                                   │
└──────────────────────────────────────────────────────────────────────┘
                    ▲ UDP 100 Mbps + PPS
┌──────────────────────── Jetson（Linux） ─────────────────────────────┐
│ CaptureThread ─► 帧环形缓冲（时间戳来自 CAM_TRIGGER）                  │
│ VoThread（每帧 30 Hz）─► VO_VELOCITY                                   │
│ MatchThread（关键帧 ~1 Hz）─► 正射校正 ─► 粗匹配 ─► 精匹配 ─► POSITION_FIX │
│ Terrain3DThread（~0.5 Hz）─► 滑窗 SfM ─► 局部 DSM ─► DSM 配准 ─► POSITION_FIX │
│ TileManager ─► 按先验预加载参考瓦片（DOM / DSM / 预提取特征）            │
└──────────────────────────────────────────────────────────────────────┘
```

**关键设计决策**：

1. **滤波器只在 MCU 上运行**。Jetson 只产生量测（速度、位置），不持有导航状态。这样 Jetson 任何异常最多导致“缺少修正”，不会让导航输出中断或跳变。
2. **量测带曝光时刻时间戳**，MCU 用状态历史缓冲回溯到量测时刻计算新息（处理 30–400 ms 的图像处理延迟）。
3. **单一写者**：只有 NavTask 调用 `NavCore`，其余任务/中断通过无锁队列投递数据，无需互斥锁，避免优先级反转。

## 3. 导航 MCU 固件

### 3.1 任务与中断

| 名称 | 类型 | 优先级 | 周期 | 内容 | 估计耗时* |
|---|---|---|---|---|---|
| IMU_DR ISR | 中断 | 最高 | 2 kHz | 4 路 SPI DMA 读取、IMU 阵列融合、5 点平均降采样到 400 Hz、入队 | < 30 µs |
| CAM_TRIG ISR | 定时器中断 | 高 | 30 Hz | 记录触发沿时间、入队 | < 5 µs |
| NavTask | RTOS 任务 | 高 | 400 Hz | 出队量测 → 量测更新；出队 IMU → 时间更新；30 Hz 输出 | 平均 < 0.8 ms |
| LinkTask | RTOS 任务 | 中 | 1 kHz 轮询 | 以太网收发、帧解码、相机触发消息、`NAV_PRIOR` 10 Hz | < 50 µs |
| SensorTask | RTOS 任务 | 中 | 50 Hz | 读大气数据/雷达高/磁强计并入队 | < 100 µs |
| HealthTask | RTOS 任务 | 低 | 1 Hz | 自检、看门狗、温控、SD 卡日志落盘 | — |

\* 估计值，需在目标板上实测（用 DWT 周期计数器剖析）。

### 3.2 IMU 阵列处理（`imu_array.hpp`）

1. 每片 IMU：`ω = M_g (ω_raw − b_g0 − k_g ΔT)`，`f = M_a (f_raw − b_a0 − k_a ΔT)`，其中 M 含比例因子、轴间失准和安装矩阵，参数来自转台 + 温箱标定。
2. 逐轴取中位数作为参考，剔除偏离超限（默认 5°/s、2 m/s²）的故障片，其余平均。
3. 2 kHz → 400 Hz：5 点平均（抗混叠）。后续可升级为角增量/速度增量 + 圆锥/划桨补偿。

### 3.3 捷联惯导（`strapdown.cpp`）

当地水平 NED 编排，位置用经纬高（双精度）：

- 姿态：`q ← q ⊗ Exp((ω_ib − Cᵀ(ω_ie + ω_en)) Δt)`
- 速度：`v̇ = C f + g − (2ω_ie + ω_en) × v`，正常重力 Somigliana 模型
- 位置：梯形积分，`φ̇ = v_N/(R_N+h)`，`λ̇ = v_E/((R_E+h)cosφ)`，`ḣ = −v_D`

600 km/h 下牵连角速度 `ω_en` 约 2.6×10⁻⁵ rad/s，与地球自转同量级，必须保留。

### 3.4 ESKF（`eskf.hpp / eskf.cpp`）

**误差状态（20 维）**

| 索引 | 状态 | 模型 |
|---|---|---|
| 0–2 | 位置误差 δp（NED，m） | — |
| 3–5 | 速度误差 δv | — |
| 6–8 | 姿态误差 φ（导航系，`C_true = (I+[φ×])C`） | — |
| 9–11 | 陀螺零偏 | 随机游走 |
| 12–14 | 加计零偏 | 随机游走 |
| 15–16 | 水平风 | 一阶马尔可夫（τ = 600 s） |
| 17 | 气压高度偏差 | 一阶马尔可夫（τ = 1800 s） |
| 18 | 视觉里程计尺度误差 | 随机游走 |
| 19 | 磁航向偏差 | 一阶马尔可夫（τ = 3600 s） |

**误差动力学**（协方差以 100 Hz 传播，`Φ ≈ I + AΔt`）：

- `δṗ = δv`
- `δv̇ = −[(2ω_ie+ω_en)×]δv − [(Cf)×]φ − C δb_a`
- `φ̇ = −[(ω_ie+ω_en)×]φ − C δb_g`

**量测模型**

| 量测 | h(x) | 主要雅可比 | 门限 |
|---|---|---|---|
| 景象匹配位置 | 水平位置 | `H_p = I₂` | χ²(2) 99.9% |
| 三维地形匹配 | 位置（含高度） | `H_p = I₃` | χ²(3) |
| VO 机体速度 | `(1+k) Cᵀ v` | `H_v=(1+k)Cᵀ`，`H_φ=(1+k)Cᵀ[v×]`，`H_k=Cᵀv` | χ²(3) |
| 真空速 | `‖v − w‖` | `H_v=uᵀ`，`H_w=−u_{NE}ᵀ` | χ²(1) |
| 气压高度 | `h + b_baro` | `H_pD=−1`，`H_b=1` | χ²(1) |
| 磁航向 | `ψ + b_m` | `H_φ=[−C₀₀C₂₀/d, −C₁₀C₂₀/d, 1]`，`H_bm=1` | χ²(1) |
| 雷达高 + DEM | `h − DEM(p)` | `H_p=[−∂DEM/∂N, −∂DEM/∂E, −1]` | χ²(1) |

更新采用 Joseph 形式保证协方差对称正定；超出 χ² 门限的量测拒绝并计数（完好性监测）。

> **为什么磁航向要有偏差状态**：开发中发现，若把带 0.5° 固定偏差的磁航向当白噪声以 10 Hz 融合，滤波器会对错误航向“过度自信”，进而把正确的景象匹配结果当作野值拒绝，导致 20 分钟漂移 1.3 km。加入磁航向偏差状态后，同一场景 RMS 降到 13 m。同理，VO 尺度误差也必须建模为状态。这类“时间相关误差当白噪声”是高速长航程组合导航最常见的失败原因。

### 3.5 时延量测处理（`state_history.hpp`）

- NavTask 以 100 Hz 将名义状态压入 256 深度的环形缓冲（可回溯 2.56 s）。
- 量测到达时按其曝光时刻取最近的历史状态，在该状态上计算新息和雅可比，修正量作用于当前状态。
- 对 250 ms 时延的景象匹配，近似误差来自这段时间内误差状态的变化，量级为 速度误差 × 0.25 s（< 1 m），可忽略。
- 升级路径：若需更严格处理，改为随机克隆（Stochastic Cloning）：曝光时刻把位置/姿态克隆进状态向量，量测到达后对克隆状态更新。

### 3.6 模式管理（`nav_core.cpp`）

| 模式 | 进入条件 | 输出 health 位 |
|---|---|---|
| M0 GNSS/INS | GNSS 可用且通过一致性检查 | — |
| M1 视觉辅助 | 30 s 内有被接受的景象匹配 | — |
| M2 地形辅助 | 30 s 内只有三维地形/TERCOM 修正 | — |
| M3 推算 | 30 s 内无任何绝对修正 | `VO_LOST`（若 VO 也中断） |
| M4 重捕获 | 水平 1σ > 300 m | `COV_LARGE`，Jetson 收到后扩大搜索窗口 |

### 3.7 30 Hz 输出

- `NavCore::onImu` 内按输出周期（33.3 ms）生成 `NavOutput`，与量测到达完全解耦。
- 输出包含：经纬高、NED 速度、欧拉角、去零偏角速度、水平/垂直 1σ、模式、健康字。
- 同时发给飞控（UART 921600）和 Jetson（UDP，用作匹配先验）。
- 输出频率为配置项（`NavCoreConfig::output_rate_hz`），可提高到 100 Hz。

## 4. 视觉计算机软件（Jetson）

### 4.1 采集（CaptureThread）

- 相机设为外触发模式，帧缓冲预分配为环形缓冲（零拷贝到 GPU，使用统一内存）。
- 每帧与 MCU 的 `CAM_TRIGGER(frame_id, t_mid_exposure)` 按帧号配对，作为该帧唯一时间戳。

### 4.2 视觉里程计（VoThread，30 Hz）

1. 金字塔 LK 光流跟踪（VPI 或 OpenCV CUDA），保持 300–500 个特征点，按网格均匀分布。
2. RANSAC 估计帧间单应矩阵，结合姿态（来自 `NAV_OUTPUT`）去除旋转，得到地面平面平移。
3. 尺度：城区/山地用雷达高度表；**林区用“气压海拔 − DEM 地形高”或 SfM 地表高**（雷达在林区可能测到树冠）。
4. 输出机体系速度和协方差（由内点数、单应残差、高度不确定度决定）。

### 4.3 景象匹配（MatchThread，约 1 Hz）

1. **选关键帧**：清晰度（拉普拉斯方差）、纹理量、可匹配性地图评分。
2. **正射校正**：用帧时刻的姿态和高度（DSM 辅助）把实时图投影到地面，统一为参考图分辨率和北向朝向。
3. **加载参考区域**：`TileStore::tilesForWindow` 按先验 3σ 窗口取瓦片（预提取特征已在 SSD 上）。
4. **粗匹配**：全局描述子检索或相位相关，得到 Top-K 候选。
5. **精匹配**：SuperPoint + LightGlue（TensorRT FP16/INT8），RANSAC 单应 / 相似变换，得到位置和航向。
6. **质量评估**（`gradeMatch`）：内点数、峰值旁瓣比、次优/最优歧义比 → 量测 σ；不合格不上报。
7. 发送 `POSITION_FIX`（时间戳 = 该帧曝光中点）。

### 4.4 三维地形匹配（Terrain3DThread，约 0.5 Hz）

1. 以 1 s 间隔的关键帧组成滑窗（基线约 167 m，B/H ≈ 0.17），用 VO 位姿做初值，局部 BA 后稠密匹配，重建航迹下方带状 DSM（高程精度约 0.5–1 m）。
2. 与参考 DSM 做高程相关搜索 + ICP 精配准，得到三维位置修正。
3. 森林区以冠层表面 DSM 作为参考，对季节、光照不敏感。

### 4.5 TERCOM（MCU 或 Jetson 均可运行）

`Tercom<MaxPts>`：累计 5–10 km 剖面，在 ±search 范围内网格搜索，代价为**去均值均方差**（对气压高度偏差不敏感），输出最优平移、代价和歧义比。单元测试中对合成山地 DEM 可准确恢复 (+120, −90) m 的偏移。

### 4.6 参考库管理

- 瓦片：0.01° × 0.01°（约 1 km）网格，每瓦片含 DOM（1 m 灰度 JPEG）、DSM（2 m float16）、预提取特征（关键点 + 描述子）、可匹配性评分。
- 飞行中按先验位置和航向预取前方 20 km 走廊的瓦片到内存，LRU 淘汰。
- 离线工具链（地面站，C++/Python）：坐标统一 → 正射/真正射 → 多时相配准 → 切瓦片 → 特征预提取 → 可匹配性评估 → 打包 + 哈希。

## 5. 通信协议（`protocol.h`）

帧格式：`A5 5A | msg_id | len | seq(2) | payload | crc16(2)`，CRC-16/CCITT-FALSE，小端，1 字节对齐。

| ID | 消息 | 方向 | 频率 |
|---|---|---|---|
| 0x01 | `NAV_OUTPUT` | MCU → 飞控 / Jetson | 30 Hz |
| 0x02 | `TIME_SYNC` | MCU → Jetson | 1 Hz（配合 PPS） |
| 0x03 | `CAM_TRIGGER` | MCU → Jetson | 每帧 |
| 0x04 | `NAV_PRIOR` | MCU → Jetson | 10 Hz |
| 0x10 | `VO_VELOCITY` | Jetson → MCU | 30 Hz |
| 0x11 | `POSITION_FIX` | Jetson → MCU | 0.5–2 Hz |
| 0x20 | `HEALTH` | 双向 | 1 Hz |

带宽：MCU↔Jetson 总计 < 50 kB/s；MCU→飞控 30 Hz × 82 字节 ≈ 2.5 kB/s，921600 bps 串口余量充足。

## 6. 飞控集成（ArduPilot）

- **推荐**：在 ArduPilot `AP_ExternalAHRS` 框架下新增一个后端（参照已有的 VectorNav / InertialLabs 后端），解析 `NAV_OUTPUT`，设置 `EAHRS_TYPE` 为该后端、`AHRS_EKF_TYPE = 11`，飞控直接使用本系统的位置/速度/姿态。
- **快速集成**：MCU 额外输出 MAVLink `GPS_INPUT`（位置/速度/精度），飞控 EKF3 当作 GPS 融合，无需改飞控代码，适合早期试飞。
- 降级：本系统 health 异常或链路中断 > 0.5 s 时，飞控切回自身 EKF（姿态仍可靠），并执行预设的航向保持/返航逻辑。

## 7. 编码规范与可靠性

- C++17 子集：无异常、无 RTTI、无运行期动态内存（Jetson 侧热路径同样预分配）；参考 MISRA C++:2023 / AUTOSAR C++14 子集，用 clang-tidy + cppcheck 静态检查。
- 所有矩阵尺寸编译期确定（`Mat<R,C>` 模板），栈使用可静态分析。
- 双精度用于位置和协方差；STM32H7 硬件双精度 FPU 支持。
- 看门狗：MCU 独立看门狗 100 ms；Jetson 服务由 systemd 守护，崩溃自动重启，MCU 侧只表现为短时缺少修正。
- 数据记录：MCU 记录原始 IMU 和全部量测到 SD 卡，Jetson 记录关键帧图像，用于事后回放和算法迭代。

| 协议 | 编解码往返、噪声字节同步、CRC 篡改检测 |

### 8.2 闭环仿真（`sim/sim_main.cpp`）

场景：600 km/h、1500 m 海拔，20 分钟 200 km，含三次 30–45 s 协调转弯；商用级 MEMS（陀螺零偏 10°/h、加计零偏 2 mg、ARW 0.3°/√h、比例因子 500 ppm）；VO 30 Hz（0.8% 尺度误差，600–610 s 丢失）；景象匹配每 30 s（σ 10 m，250 ms 时延，5% 错误匹配，600–720 s 无修正模拟森林弱纹理区）；三维地形匹配每 60 s；空速、气压（25 m 偏差）、磁航向（0.5° 偏差）。

| 场景 | 结果（种子 1） |
|---|---|
| A 完整组合导航 | 水平 RMS **13.4 m**，最大 41.5 m（出现在 2 分钟无景象匹配区段末尾）；输出 **30.0 Hz**；错误匹配全部被拒 |
| A，8 组随机种子 | 水平 RMS 7.3–14.2 m，最大 21.8–56.8 m |
| B 仅 VO + 空速 + 磁（无绝对修正） | 1 / 5 / 10 分钟：9 / 41 / 444 m |
| C 纯惯导（仅气压定高） | 1 / 5 / 10 分钟：113 / 1630 / 2133 m |

说明：场景 C 比总体方案 §6.1 的解析估计（10 分钟约 17 km）小，是因为仿真航迹中的转弯机动配合气压高度，使水平姿态误差和陀螺零偏变得可观测（滤波器在第一次转弯时把陀螺零偏估计到了真值附近），这也印证了“进入长时间失配区前安排机动”的建议。

已知局限：仿真用同一套机械编排生成真值，未包含杆臂、振动、温漂和图像级误差；滤波器估计的 σ 在修正间隙末段偏乐观（σ 约 10 m 时实际误差可达 20–40 m），需要在半实物仿真阶段结合真实数据整定过程噪声。
